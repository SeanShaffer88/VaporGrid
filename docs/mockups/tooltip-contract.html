Mockup for review before implementation. Every element that can be acted on or needs explaining gets a tooltip. A tooltip never covers text, controls, fields or focus rings. When there is no free space next to the anchor, the tooltip docks into the status bar's hint lane instead of floating over content.

Icon-only buttons name themselves. Disabled controls explain why they are disabled, and keep a tooltip while disabled. Near a window edge, the tooltip flips inward instead of clipping.

Coverage: tooltips are required on

  • Every interactive control: buttons, links, fields, selects, checkboxes, tabs, menu items, dividers and resize handles
  • Icon-only controls, status chips and badges, column headers, and progress bars (current value and phase)
  • Truncated text, showing the full value
  • Disabled controls, explaining why they are disabled
  • Not required on plain body text and headings that are fully visible

Placement: never covers content

  1. Try below, above, end, then start of the anchor, with an 8px gap
  2. Reject any spot that intersects text, a control, a field, a focus ring, or the anchor itself, or that leaves the window
  3. If no spot fits, show the text in the status bar hint lane
  4. Max 320px wide, wrapping text; never clipped or scrolled

Behavior

  • Shows on hover after 500 ms; on keyboard focus right away; on touch, long-press 500 ms
  • Hoverable, so the pointer can move onto it; stays while the anchor is hovered or focused; Esc dismisses
  • Linked with aria-describedby; native title banned
  • Content: one sentence, plus the shortcut if one exists; no essential info that exists only in the tooltip
  • Style: Raised fill, border, rim; 13px text; no arrow tip overlapping content; reduced motion → no fade
